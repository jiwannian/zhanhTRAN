# zhanhTRAN

<img src="icons/icon-128.png" width="64" height="64" alt="zhanhTRAN">

Zotero 自定义模型翻译插件。使用本地 Python 解析 PDF、扫描件和图片，通过用户配置的供应商翻译，并输出保持源布局的译文与左右并排双语文件。

## 功能

- 多供应商：名称、Base URL、API 密钥、模型、目标语言；支持 OpenAI 兼容与 Anthropic 原生协议。
- 本地 PDF 文本、OCR、图片文字与表格解析，结构化翻译和公式保护。
- 译文、双语可独立开关；双语可选择原文左或译文左。
- PDF 输出仍为 PDF；图片保留原扩展名。不创建笔记或额外 Markdown/HTML 附件。
- 点击翻译直接开始，可移动进度窗、取消任务、中断最多自动重试 5 次。
- 设置中可选 1–10 个并发翻译请求（默认 2 个）；返回乱序时仍按原文顺序回填，遇到限流自动降低并发。
- PDF 固定在原文字区域内排版，先尝试原字号，放不下时寻找可完整容纳的最大字号；同一区域统一缩放并保留粗斜体和相对字号。不扩框、不移动相邻内容、不增高表格、不新增页面。目录序号、引导点、页码和项目符号保留原样。
- 连续正文及同一列表项按源段落合并被 PDF 拆开的视觉行，在原区域内连续排版；不按句号或模型额外换行分成小框。数字编号保留源位置和正文悬挂缩进，用主要文字的基线判断行距，避免上标或混合字体误断段。下一编号、真实段落、目录、图注及分栏边界仍保留，旧版逐行缓存可在本地导出时合并。
- 缩写表按源缩写列和释义列逐条保留：支持带空格、句点、大小写混合及单位缩写（如 `B. S.`、`C of A`、`Kg`、`MoCTCA`），不依赖全大写白名单。缩写复用原 PDF 文字，只翻译对应释义，不因右边界参差或较窄间隔而把 TTSN、Mtrs 等下一条并入上一条。源释义续行只归属于本条；可明确拆分的旧合段缓存在本地恢复，缺少或重复缩写等歧义情况明确报错，不猜测补写。
- 坐标及特殊编码引号使用占位符保护，并复用源 PDF 字形/矢量内容；新绘制文本检查缺字并使用可用字体回退。
- 输出保存在源文件旁并加入相同父条目和文库。个人文库使用链接附件；群组文库导入文件，Zotero 管理的附件副本不保证仍位于源目录。

## 安装

使用交付的 XPI，或从 [Releases](https://github.com/jiwannian/zhanhTRAN/releases) 获取已发布安装包，在 Zotero 的“工具 → 插件”中选择“从文件安装”。声明兼容 Zotero 9–10；1.0.23 的隔离验证记录见 [VALIDATION.md](docs/VALIDATION.md)，Zotero 9 尚未实机验证。插件采用手动更新，不后台更新。

安装 Python 3.10 或更高版本，建议为解析器建立独立环境：

```powershell
py -3.10 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Linux/macOS：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

在 zhanhTRAN 设置中填写该环境 Python 可执行文件的**绝对路径**，配置供应商、Base URL（不是完整接口路径）、模型和密钥，保存后进行联通测试。默认地址 `https://provider.invalid` 是不可用模板，必须替换。公开版只使用自己的设置命名空间，不自动读取其他插件的配置。

选中 PDF 或图片附件，或含此类附件的条目，通过右键菜单或工具菜单选择 zhanhTRAN 翻译。源文件不会被覆盖；同名结果已存在时会使用安全的输出路径。

## 隐私与边界

解析/OCR 在本地执行；提取的文本会发送至所选模型供应商。密钥使用 Zotero 登录管理器保存，不放入明文偏好或安装包。请自行确认供应商的数据政策与使用权限，敏感文档不要发送给未经批准的服务。

不附带 Python 环境或模型服务，不承诺完全离线。OCR、复杂表格和公式存在识别边界；保留布局并不保证字体或每个像素相同。整份 PDF 均采用固定区域缩字，没有人为字号或比例下限，因此极长译文可能非常小；不会截字、省略、借用邻区或续页。无效坐标、缺失符号、不可用字形或渲染数值失效时，报告具体区域，不交付部分 PDF。独立图片文件仍使用原有排版路径。

## 开发与测试

排障、可复用方法和“症状 → 源码 → 测试”索引见 [工程经验](docs/ENGINEERING_LESSONS.md)；当前版本实测范围见 [验证记录](docs/VALIDATION.md)。

需要 Node.js 22+、Python 3.10+：

```sh
npm ci
npx playwright install chromium
python -m pip install -r requirements-dev.txt
npm test
python -m coverage run --source=src -m unittest discover -s tests -p '*_test.py'
python -m coverage report --fail-under=80
python tools/package.py
```

JS/Python 桥接测试使用 `ZHANHTRAN_PYTHON` 指定已安装依赖的 Python 绝对路径；未设置时，从 PATH 中的 `python` 读取 `sys.executable` 获取绝对路径。OCR 测试需要 CJK 字体：Windows 默认查找微软雅黑，Linux 查找文泉驿正黑；也可设置 `ZHANHTRAN_TEST_FONT`。Ubuntu 可安装 `fonts-wqy-zenhei`。`ZHANHTRAN_CHROME` 可指定用于 UI 测试的 Chromium/Chrome，否则使用 Playwright Chromium。

测试只使用合成输入及模拟供应商。单元/集成和浏览器测试不是真实供应商翻译质量或 Zotero 原生端到端测试的替代品。构建结果为 `dist/zhanhTRAN-1.0.23.xpi`，相同源码与 Python 压缩运行环境可重现相同包字节。

## 1.0.18 排版规则

PDF 的正文、标题、图注、脚注、目录标题、表格单元格及 OCR 文字各有固定区域。依据有效源文字行坐标补取旧缓存的几何、基线和对齐信息，排除纯空白片段；保留首行/悬挂缩进，图注居中、页码右对齐。先按原字号检查实际可见字形，再通过逐次减半和二分找到可完整容纳的最大比例，比例精度为原字号的 0.1%。缩进和区域位置不随字号缩放。

坐标保护覆盖列表段落、多字体片段、空格分隔、常见单/双引号及 `U+201F` 特殊编码。坐标整体按所在区域的比例缩小，列表标记、目录编号、引导点和页码仍留在原位置。文档继续使用 `schema: 1`，CLI 保持单 JSON 标准输出和独立 stderr 进度；报告记录固定区域、原字号、实际字号、比例及一一对应的页面映射，续页序号恒为 0。

此次不新增设置，不修改供应商、密钥、Python 路径、输出选项或并发配置；并发仍为默认 2、范围 1–10。更新后建议重新发起翻译；旧缓存能补取源几何和未变动的坐标，但缺失占位内容仍会明确报错。交付包供手动安装，不自动更新日常 Zotero。

## 历史修复

下列版本描述记录各版本当时的行为；PDF 的续页、表格增高及 OCR 扩框自 1.0.18 起由上述固定区域缩字规则替代。独立图片输出保持原行为。

1.0.23 补齐带空格、句点、混合大小写及小写单位的缩写表识别；依据重复两列的几何关系选择完整缩写，不把内部空格当成列间隔，也不因较长缩写后的间隔小于两倍字号而漏行。逐行保留源列起点，已有正确缩写行可作为旧缓存的列锚点但不重复输出；修正旧版把 `B. S.` 的 `B.` 当作列表编号后在释义中残留 `S.` 的情况。合成 A/B 中 `MoCTCA` 与 `Mtrs` 从错并一行恢复为各自原行。歧义旧缓存仍明确失败；固定区域、正文连续性、供应商配置、并发及独立图片行为不变。

1.0.22 修复无边框缩写表被误合并为连续正文、TTSN 等缩写没有独立行的问题。依据重复对齐的缩写列、释义列及物理间隔识别条目，保留原生缩写、列位置、行位置与样式，只把释义交给模型；同一释义的源续行保留在自身区域，不吞下一条。旧合段缓存仅在各缩写唯一、齐全、顺序正确且没有样式/符号歧义时按源缩写拆分；否则报告具体区域并要求重新翻译，不静默漏行。普通正文连续排版、固定区域缩字、供应商配置、并发及独立图片行为不变。

1.0.21 修复裸数字及带点/括号编号未独立保护，导致首行与续行分开翻译、正文起点错误的问题。基于源数字与正文间的实际间隔识别编号，同一列表项正文合并，下一编号保持独立；不把普通年份、时间、小数或数量误作列表。混合字体及上标导致的字框顶部偏移不再参与段落行距判断，改用主要文字基线。旧逐行缓存可补取源信息、去除重复编号并重组正文，逐区域符号和样式完整性校验保持不变。固定区域、整段统一缩字、并发及独立图片行为不变。

1.0.19 修复私有字体列表标记（例如 `U+F0A7`）已从正文分离，却又被登记为正文占位符，导致误报“译文结构不完整”的问题。只在正文实际替换成功后登记受保护内容，并依据位置区分列表标记与正文中的相同符号；标记字体也不再把整段列表误判为公式。导出时可剔除 1.0.18 缓存中经源 PDF 确认属于独立列表标记、且源译文都没有引用的孤立元数据。正文坐标、公式、样式或真正缺失的占位符仍严格校验；固定区域缩字、字号关系、并发及独立图片行为不变。

1.0.3 修复页底脚注因固定文本框过矮导致生成失败，脚注支持按原字号续排；短标题不再被源文字宽度限制为窄栏。普通表格按完整单元格翻译并复用源字号，算法和公式保留原有保护路径。坐标符号按源基线与译文对齐。

1.0.4 修复目录把字形边界当作行框导致生成失败的问题。目录按源基线排版，长标题可换行和续页，编号、引导点与页码列保持各自位置；后续条目同步顺延。引导点使用独立字体资源，避免部分 PDF 阅读器将其显示为空白。中文正文统一字体回退，并使用可用的独立粗体字形。字体按文档预先子集化并复用，旧环境缺少 fontTools 时仍可使用完整系统字体。排版失败信息直接显示页码和区域 ID。

1.0.6 修复图中 OCR 标签因识别框过紧而无法生成的问题。OCR 标签单独保存、估算字号，不继承附近正文的字体大小；原框放不下时仅借用图内右侧或下方经像素检查确认的空白区域，不缩小字号、不向左移动，也不跨越其他标签、图表线条或批注。确实无空间时继续报告具体区域，不截断译文。图片输出同步复制扩展后的完整文字区域。

1.0.7 修复紧邻地图标注或线条时，极窄 OCR 框中的短汉字译文仅差少量宽度也无法生成的问题。在借用安全空白失败后，仅对纯汉字短标签采用原字号、原位置的逐字排版，最多收紧每个字间距 0.045 em；不压缩字形，不用于混合文字或超长译文，仍无空间时继续报告具体区域。

Windows 原生端到端验收可在构建后运行 `python tools/run-native.py`，默认查找标准安装路径的 Zotero，也可用 `ZHANHTRAN_ZOTERO` 指定。它创建独立 profile、独立文库和回环模拟供应商，不安装到日常配置。运行可能打开测试窗口，结果与截图仅保存在被 Git 忽略的 `qa/`、`logs/`。

1.0.8 修复偏移空白行误判为首行缩进，以及表格、居中页眉误判为正文分栏造成的生成失败。解析时排除纯空白行的字体、行距和缩进，排版按实际正文行核对分栏，保留真实双栏与原字号。横向越界失败会记录具体区域和坐标。设置中的并发翻译请求仍为默认 2、范围 1–10。

1.0.9 为可识别的原生矩形网格表格增加自动行高和续表。按原字号、列宽与单元格样式测量译文，并预留实际字形上下边界；增高行推动后续行、后续表格及未改变的正文。正常行整行分页，超高单行按自然换行跨页，续页重复已识别的内部表头，短列结束后保留同一行空白。保留网格线的颜色、粗细、虚线与规则矩形底色；未增高的页面沿用原绘制路径。表格映射写入排版报告，旋转页的书签和内部跳转统一按未旋转坐标映射。合并单元格、复杂绘图或超高重复表头无法安全重建时，继续按具体单元格报告失败，不交付截断文件。

1.0.10 修复地图中短中英文混排 OCR 标注的矩形空间误判。常规排版、矩形空白扩展及纯汉字微调都失败后，按原字号和原框宽度试排完整混排文字，检查每行实际范围和透明字形的像素占用；第二行右侧未使用的空白不再误挡排版。扩展区不填充背景，保留邻近图标和纹理；已识别标注、批注、表单、已放置译文和实际冲突的高对比图形仍受保护。记录行框、实际占用范围和换行数。字体不缩小，横向起点不变，无法完整容纳时仍报告具体区域。

1.0.11 修复由细长填充矩形和交点方块组成的原生表格未进入自动增高流程的问题。完整网格识别兼容解析坐标偏差，保留实际边框位置、粗细、颜色和原字号；中英文单元格可增高及续排，后续正文顺延。不需要增高的表格保持原矢量边框，无法识别的网格报告具体原因。

1.0.12 修复相邻 OCR 识别框重叠时，坐标舍入误差及空白字形边界误挡混排标签的问题。按坐标容差和实际字形判断碰撞，原宽度放不下时检查右侧可用区域；较高字形可在原排版框内预留最多 1 pt 的顶部空白，仍保留原字号和左侧对齐。已知文字、批注、表单、先前译文和实际边线继续受保护。

1.0.13 将原有逐字形避让扩展到纯中文及含中文标点的短 OCR 标签。相邻识别框重叠、矩形扩框被空白字形旁的细线阻挡时，仍可按原字号检查完整标签的实际字形占用；安全时使用右侧空白或原宽度换行。继续保留左上锚点、边界、碰撞检查和失败报告，不改动正文及表格续排流程。

1.0.14 修复 OCR 框位于小数坐标时，原字抗锯齿边缘与字形检查留边在原框左侧或上方造成的误碰撞。背景像素检查只覆盖允许向右、向下借用的区域，与矩形扩框保持一致；仍完整检查已知文字、批注、表单和先前译文，实际字形不向左或向上移动，字号及碰撞阈值不变。

1.0.15 修复倾斜或弧形 OCR 标签的外接框高度被误当成字高，导致字号估计过大、无法生成 PDF 的问题。保留识别四角坐标，按识别方向的框边估算字号，再换算到每处图片的页面坐标；窄单字不误判为竖排。译文沿用这一源文字估计字号，不按译文长度缩小，也不改动左上锚点、碰撞检查或正文与表格排版。文档仍为 schema 1，旧数据缺少四角坐标时保留原有行为。

1.0.16 修复紧邻双行 OCR 标注中的数字与中文混排因字体空白上下边界无法排入原框的问题。正常排版候选全部失败后，按完整可见字形的上下范围重新对齐基线，并保留抗锯齿边缘余量；不缩放、截断或移动左上锚点。新增候选仍须通过原有文字、图形、批注、表单和先前译文的碰撞检查，旧成功路径不变。

仅验收排版桥接时，可设置环境变量 ZHANHTRAN_QA_LAYOUT_ONLY=1 后运行 tools/run-native.py；默认仍执行原有完整原生验收。
